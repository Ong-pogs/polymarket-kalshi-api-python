Build me a small, read-only Python tutorial project that reads Polymarket and Kalshi through the Predictefy API with one package. The point is that the same function works on both venues without changes. It must never place an order and never ask for a wallet key or a venue login.

STACK
- Python 3.10 or newer, a virtual environment, and one dependency pinned exactly: predictefy==1.0.0b9 (PyPI). Check PyPI for the current version before pinning. pytest for tests only.
- Files: common.py, chart.py, step1_first_call.py, step2_same_code_kalshi.py, step3_order_book.py, step4_compare_venues.py, step5_price_history.py, step6_backtest.py, step7_replay_backtest.py, tests/, requirements.txt, .env.example, .gitignore, README.md, LICENSE (MIT).
- Read PREDICTEFY_API_KEY from the environment or a local .env file. Treat the placeholder in .env.example (pk_live_your_key_here) as "not set" and exit with a message that points to https://portal.predictefy.com/keys. Never print or log the key. .gitignore must list .env, .venv/, data/, out/ and recordings/.
- Keep every script short enough to read on one screen, with lines under 100 characters, and put the cost in credits in each file's docstring.

THE CLIENT
- from predictefy import Predictefy; client = Predictefy(api_key=...). Venue clients share one method shape: client.polymarket, client.kalshi, or client.exchange("kalshi") when the venue is a variable. Cross-venue calls live on client.router.
- List methods return a list with .page and .meta. Records are plain dictionaries.
- Pass the client an httpx transport that reads the X-Credits-Charged response header, so every script can end with a line such as "credits used: 12   [fetchMarket 1 x2, fetchOrderBook 5 x2]".
- The same transport supports PREDICTEFY_RECORD=<folder> (save every JSON response under <folder>/<name of the script and its arguments>/, plus the time of the run) and PREDICTEFY_REPLAY=<folder> (answer from those files with no network and no key, freeze "now" to the recorded time, and print a first line "[replay] responses recorded <time> UTC, no API call made"). Do not record the streamed /v1/history/replay pages.
- Build the client lazily so importing a step never needs a key, and let tests install their own transport.

THE STEPS
1. step1_first_call.py: client.polymarket.fetch_markets({"query": ..., "status": "active", "sort": "volume", "limit": 3}). Print the Yes price (market["yes"]["price"], falling back to the first outcome), the marketId and the title. 1 credit.
2. step2_same_code_kalshi.py: the same search as a function search(venue, query) that uses client.exchange(venue). Run it for "polymarket" and "kalshi", print how many fields each record has and how many they share, and print title, status, resolutionDate, volume24h, volume24hUnit and url side by side. Volume is in dollars on Polymarket and in contracts on Kalshi; volume24hUnit says which. 1 credit per venue.
3. step3_order_book.py: books and candles key on an outcomeId, not a marketId. Look the market up with fetch_market(market_id), take the Yes side's outcomeId, then fetch_order_book({"outcomeId": ..., "limit": 3}) and read reply["data"]["bids"] and ["asks"] (each level has price and size). Print asks above bids with the spread between them. 5 credits per book, 1 per lookup.
4. step4_compare_venues.py: client.router.compare_market_prices({"marketId": "polymarket:<id>", "live": True}) returns one row per other venue with bestBid, bestAsk, similarity, label and matchQuality (verdict and differenceKinds). The anchor market is not in the rows, so read its own book as in step 3. Print bid, ask and mid for each venue, the difference between the mids in cents, the label exactly as sent ("indicative price comparison") and the verdict. Never call the difference arbitrage. 10 credits for the comparison.
5. step5_price_history.py: candles(venue, outcome_id, days=7, resolution="4h") calls fetch_ohlcv({"outcomeId", "resolution", "start", "end", "limit": 5000}) with ISO timestamps and returns reply["data"] without the candles whose close is 0 (an empty bucket comes back as zeros). Round the start forward by an hour so a 7-day request stays inside the free plan's 7 days. Print the number of candles, first and last close, low, high, and a count by source/sourceType. Write out/history.html with both venues' closes on one chart. 5 credits per venue.
6. step6_backtest.py: backtest(rows, lookback=6, dip=0.02, shares=100). Buy when a close is `dip` under the average of the `lookback` closes before it; sell when a close is back at that average; one position at a time. Decide on one candle and fill at the NEXT candle's close, so the rule never uses a price it could not have seen. Mark an open position at the last close. Accept --days (default 7). Catch PredictefyError: when error.code is "PLAN_REQUIRED" print the server's message, say that the free plan reads 7 days and Builder reads 12 months, and print the upgrade link https://predictefy.com/en/pricing?utm_source=youtube&utm_medium=video&utm_campaign=polymarket-kalshi-api-python&utm_content=upgrade . Write out/backtest-<venue>-<days>d.html with the buys and sells marked. Say in the file and on the chart that this is a first look: closes only, no spread, no fees.
7. step7_replay_backtest.py (Builder plan and above): with --download, save every row of client.replay_history(venue, outcome_id, kind="tob", since=..., until=..., limit=20000) to data/<venue>-<market>-tob.ndjson (the window is 31 days at most; each page costs 5 credits). Without it, replay from disk at no cost: from predictefy.backtest import Backtest, NdjsonFileFeed, Strategy; Backtest(NdjsonFileFeed(path), strategy, venue=venue, initial_cash=1000).run(). The strategy is the same rule on quotes: keep the last mid of every four-hour bar, buy at the ask when it is `dip` under the average of the last six, sell at the bid when it is back at that average, and place nothing while an order is open. Print one line per order (size, average price, number of fills, fees, time) and the result after fees. If the saved file is empty, say that Predictefy has no top-of-book rows for that outcome.

CHARTS
- chart.py writes self-contained HTML with inline SVG drawn from JSON embedded in the page: no libraries and no network. Dark surface, large type, thin 2.5px lines, hairline grid, a legend when there are two series, a value label at the end of each line, a crosshair with one tooltip for every series, and the same numbers as a table. Use blue #3987e5 for Polymarket and orange #d95926 for Kalshi. Mark buys and sells with up and down triangles and a word, not with colour. Name the endpoint the data came from under the title. Escape "</" in the embedded JSON.

TESTS (pytest, no network)
- Use httpx.MockTransport with synthetic responses in the documented envelope {"success": true, "data": ...}.
- Cover: the search sends the same query to both venues and only the path differs; the order book request keys on outcomeId; the comparison sends "venue:marketId" and prints the indicative label and never the word arbitrage; empty candles are dropped and the 7-day window starts inside 7 days; a 403 PLAN_REQUIRED becomes a message that names the plan and the upgrade link; the backtest fills at the next close and marks an open position; credits are summed from the header; a recording replays without the network and does not contain the key; a missing key exits with instructions; the replay strategy fills on a later quote and pays fees.

README
- Quick start, a table of the steps with the endpoint and credits for each, what the free plan allows (25,000 credits a month, 7 days of history, no replay route) against Builder ($48.88 a month, 500,000 credits, 12 months, replay), how to follow a different market, record and replay, and a plain list of what to know before trusting a number: a price gap is indicative, read how each candle was built, volume units differ, and a backtest is not a forecast.
